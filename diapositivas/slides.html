FUNDAMENTOS Diapositiva 2 de 17

¿Qué es Google ADK? (Agent Development Kit)

El framework de ingeniería de software de Google diseñado para construir sistemas agénticos robustos, modulares y de producción.

1

Filosofía Code-First & Tipado Estricto

Sin abstracciones opacas ni cadenas mágicas de texto. Los agentes, herramientas y estados son clases Python nativas con tipado estricto (Pydantic, typing). Lo que ves en el código es exactamente lo que se ejecuta.

2

100% Agnóstico de Modelo (Local & Cloud)

Diseñado para operar con Gemini, pero optimizado para correr 100% en local con Ollama, LM Studio, MLX o vLLM vía LiteLLM. Cero costo por token y máxima privacidad para datos corporativos sensibles.

3

Orquestación Determinista y Grafos

Combina la flexibilidad cognitiva del LLM con control de flujo determinista: agentes Secuenciales, Paralelos, Bucles iterativos (LoopAgent) y el nuevo Graph Workflow API (ADK 2.0) con aristas dinámicas y JoinNode.

4

Ecosistema Completo: ADK Web & Agents-CLI

Incluye un servidor de desarrollo interactivo con UI gráfica (adk web), soporte nativo de Human-in-the-Loop con tarjetas de aprobación interactiva, visor de topología de grafos y suites de evaluación automatizadas (ADLC).

Las Primitivas Esenciales de ADK 2.0

Desacoplamiento riguroso entre Cognición, Capacidad, Estado y Ejecución.

1. Agent / LlmAgent

Unidad cognitiva central. Define el modelo local, instrucciones con variables dinámicas y herramientas asociadas.

agent = Agent(
    name="dev_assistant",
    model=local_model,
    instruction="Asistes a {user_name}",
    tools=[my_tool]
)
2. Tool & FunctionTool

Funciones Python con anotaciones de tipo y docstrings estrictos. Soporta puertas de confirmación humana previa.

from google.adk.tools import FunctionTool

secure_tool = FunctionTool(
    func=delete_database,
    require_confirmation=True
)
3. Session & State

Almacena el historial conversacional y un diccionario clave-valor state compartido entre agentes y tools.

# Lectura y escritura en el estado
session.state["user_id"] = 42
token = session.state.get("auth_token")
4. Runner & Events

El Runner orquesta el ciclo de vida emitiendo eventos asíncronos atómicos (Event) para trazabilidad total.

async for event in runner.run_async(
    session_id=session.id,
    prompt="¿Cómo optimizo esta query?"
):
    print(event.content)

Single-Agent: Inyección Dinámica y Persistencia

Uso de placeholders en instrucciones y guardado automático con output_key.

01_basic_agent.py ADK 2.0 
from google.adk.agents import Agent

agente = Agent(
    name="asistente_dev",
    model=local_model,
    instruction="""
    Eres un {rol_asignado}.
    Asistes a {nombre_usuario}.
    
    Reglas:
    - Responde en código conciso.
    - Considera seguridad y latencia.
    """,
    output_key="ultima_respuesta"
)
Inyección Dinámica de Estado:

Los parámetros {rol_asignado} y {nombre_usuario} se extraen automáticamente de session.state en cada llamada, sin formateo manual de strings.

output_key automático:

Evita parseos manuales. El resultado final se guarda de inmediato en el estado de la sesión, listo para que otros agentes o herramientas lo consuman.

MÓDULO 1: HERRAMIENTAS Diapositiva 6 de 17

Function Calling Estricto y ToolContext

Acceso y mutación del estado conversacional desde dentro de las herramientas.

02_tools_and_context.py Python 
from google.adk.tools import ToolContext

def registrar_alerta(severidad: str, detalle: str, tool_context: ToolContext) -> dict:
    """Registra una alerta técnica de seguridad en la sesión.

    Args:
        severidad: Nivel de la alerta ('baja', 'media', 'alta', 'critica').
        detalle: Explicación de la vulnerabilidad o anomalía.

    Returns:
        dict con el estado de guardado y total de alertas.
    """
    # Acceso directo al estado de la sesión activa
    alertas = tool_context.state.get("alertas", [])
    alertas.append({"severidad": severidad, "detalle": detalle})
    tool_context.state["alertas"] = alertas
    
    return {"status": "success", "total_alertas": len(alertas)}
1. Docstring Obligatorio

El LLM decide usar la herramienta basándose únicamente en la descripción.

2. Type Hints Estrictos

Anotaciones de tipos en todos los argumentos (evitar tipos genéricos o ANY).

3. Retorno JSON (dict)

Devolver estructuras diccionario serializables para consumo del modelo.

4. ToolContext Oculto

No mencionar tool_context en el docstring; ADK lo inyecta por el framework.

Human-in-the-Loop: Puertas de Confirmación

Garantizando que acciones destructivas o críticas requieran autorización explícita.

03_human_confirmation.py Python 
from google.adk.tools import FunctionTool

# 1. Confirmación incondicional
tool_borrado = FunctionTool(
    borrar_base_datos,
    require_confirmation=True
)

# 2. Confirmación basada en regla
def requiere_aprobacion(servicio: str, **kwargs) -> bool:
    return servicio in ["postgresql", "redis"]

tool_reinicio = FunctionTool(
    reiniciar_servicio,
    require_confirmation=requiere_aprobacion
)
Intercepción Automática por el Runner:

Cuando el LLM decide llamar a la función, el Runner suspende el turno y emite un evento de confirmación hacia la interfaz de usuario antes de ejecutar el código.

Auditoría y Resumability:

Permite guardar la sesión en base de datos y reanudar la ejecución únicamente tras la firma o clic del operador humano.

MÓDULO 2: ORQUESTACIÓN Diapositiva 10 de 17

Bucles de Refinamiento: LoopAgent & Escalation

Ciclos iterativos de Generación -> Evaluación -> Parada Temprana.

03_loop_refinement.py Python 
class EscalationChecker(BaseAgent):
    async def _run_async_impl(self, ctx):
        res = ctx.session.state.get("evaluacion")
        if res and "APROBADO" in res:
            # Detiene el bucle inmediatamente
            yield Event(
                author=self.name,
                actions=EventActions(escalate=True)
            )
        else:
            yield Event(author=self.name)

loop = LoopAgent(
    name="refinador",
    sub_agents=[generador, evaluador, EscalationChecker("stop")],
    max_iterations=4  # Circuit breaker
)
1. Generar Código:

El agente programador produce una solución inicial o iterada.

2. Evaluar Rigurosamente:

El agente evaluador revisa tipado, tests y complejidad algorítmica.

3. EscalationChecker:

Si la nota es suficiente, activa escalate=True para terminar inmediatamente sin agotar todas las iteraciones.

MÓDULO 3: GRAFOS Diapositiva 11 de 17

La Revolución de ADK 2.0: Graph Workflow API

Grafos Dirigidos de Nodos y Aristas para flujos dinámicos e interactivos.

01_graph_basics.py ADK 2.0 Graph API 
from google.adk.workflow import Workflow

def normalizar_texto(node_input: str) -> str:
    return node_input.strip().upper()

# Auto-wrapping: Funciones Python y LLMs se convierten en nodos automáticamente
grafo = Workflow(
    name="soporte_workflow",
    edges=[
        ("START", normalizar_texto),
        (normalizar_texto, agente_experto)
    ]
)
START Built-In:

Nodo de entrada estándar que recibe la petición o prompt del usuario.

Auto-wrapping:

No necesitas envolver funciones ni agentes a mano; ADK crea FunctionNodes automáticamente.

Resolución de Parámetros:

node_input recibe la salida del predecesor; otros argumentos se extraen de ctx.state.

MÓDULO 3: GRAFOS Diapositiva 12 de 17

Enrutamiento Condicional en Grafos

Bifurcaciones por condición y rutas por defecto (__DEFAULT__).

02_conditional_routing.py Python 
def clasificador(node_input: str) -> Event:
    if "error" in node_input:
        return Event(output=node_input, route="codigo")
    elif "vulnerabilidad" in node_input:
        return Event(output=node_input, route="seguridad")
    return Event(output=node_input, route="__DEFAULT__")

grafo = Workflow(
    name="router_dinamico",
    edges=[
        ("START", clasificador),
        (clasificador, agente_codigo, "codigo"),
        (clasificador, agente_seguridad, "seguridad"),
        (clasificador, agente_general, "__DEFAULT__"),
    ]
)
Event con route:

El nodo emite el objeto Event con el payload en output y el identificador de rama en route.

Garantía de Fallback:

La arista especial __DEFAULT__ evita bloqueos en el grafo si ninguna condición coincide con la intención.

MÓDULO 4: MULTI-AGENT Diapositiva 15 de 17

Task Delegation Tipada con Pydantic (ADK 2.0)

Contratos de datos estrictos mediante mode='task', request_task y finish_task.

02_task_delegation_pydantic.py ADK 2.0 Task Mode 
from pydantic import BaseModel, Field
from google.adk.agents import Agent

class AuditReport(BaseModel):
    score: int = Field(description="Calificación de 0 a 100")
    aprobado: bool = Field(description="True si cumple todos los requisitos")

auditor = Agent(
    name="auditor",
    model=local_model,
    mode="task",                # ADK inyecta automáticamente 'finish_task'
    output_schema=AuditReport,  # Contrato Pydantic garantizado
    description="Audita la arquitectura de software."
)

coordinador = Agent(
    name="coordinador",
    model=local_model,
    sub_agents=[auditor]        # ADK inyecta automáticamente 'request_task_auditor'
)
💡 Cero Alucinaciones de Estructura: El coordinador recibe un objeto Python fuertemente validado por Pydantic antes de proseguir su razonamiento.

Mejores Prácticas de Ingeniería (ADLC)

Directrices de producción basadas en google/agents-cli.

Optimización de Modelos Locales
  • Mantén temperaturas bajas (0.1 - 0.2) para maximizar la fidelidad en llamadas a herramientas.
  • Usa modelos con soporte nativo de function calling (Qwen 2.5 7B/14B).
  • Limpia el contexto entre fases con include_contents='none' si un subagente sólo necesita la última tarea.
Evaluación y Observabilidad
  • Crea datasets dorados y evalúa con agents-cli eval run antes de pasar a producción.
  • Aplica "LLM-as-a-judge" con rúbricas de grading reproducibles.
  • Monitorea eventos de parada y tiempos de latencia con OpenTelemetry.
